## Story
**Como** lead que quer marcar uma prova,
**quero** que o agendamento seja criado de fato no ERP, sem duplicar se eu confirmar duas vezes,
**para que** minha vaga exista de verdade quando eu chegar na loja.

## Acceptance Criteria
1. `consultar_slots` retorna vagas reais via `GET /agenda/slots` (§7.2).
2. `agendar` cria o registro via `POST /agenda`, idempotente por `(tenant_id, lead_id, data, hora)` (I6).
3. Escrita de agenda usa **Leitura e escrita** — o único recurso da WebLocação com esse nível de acesso (§7.1); todo o resto é leitura.
4. Falha de escrita não deixa o lead sem retorno: aciona `abrir_transbordo` e informa que vai confirmar (I2, P3).

### Schema (fonte literal: PRD §17.7)
```sql
create table agendamentos (
  id uuid primary key default gen_random_uuid(),
  tenant_id uuid not null references tenants(id) on delete cascade,
  wl_agendamento_id text,
  lead_id uuid references leads(id) on delete set null,
  tipo text not null,
  data date not null,
  hora time not null,
  cliente_nome text,
  cliente_telefone text,
  produto_ref text,
  origem text not null default 'automacao',
  status text not null default 'ativo',
  sincronizado_em timestamptz not null default now(),
  unique (tenant_id, wl_agendamento_id)
);
```
