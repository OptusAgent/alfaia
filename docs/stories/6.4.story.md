## Story
**Como** plataforma que não deixa lead esfriar,
**quero** que um worker detecte silêncio além da janela configurada e prepare o follow-up,
**para que** o lojista só precise clicar para disparar, sem monitorar manualmente cada card.

## Acceptance Criteria
1. Lead em `orcamento`, `qualificando` ou `negociando` sem resposta há `janela_silencio_horas` (padrão 24h) → move para `follow_up` e o botão de disparo fica ativo (AC 10.1).
2. Lead responde → volta para `negociando`, contador de tentativas zera (AC 10.3).
3. `max_tentativas` atingido (padrão 3) → `descartado` automático com motivo `sem_resposta` (§10.2).
4. Silêncio nunca é confundido com desistência explícita — este worker só move para `follow_up`/`descartado` por tentativas esgotadas, nunca classifica como "desistência" (AC 9.11, distinção já estabelecida em 3.5).
5. Jobs `followup_scan` (15 min) e `followup_expirar` (1h) implementados conforme §18.3.

### Índice de suporte (fonte literal: PRD §17.4)
```sql
create index leads_followup on leads(tenant_id, followup_proximo_em)
  where status in ('orcamento','qualificando','negociando','follow_up');
```

### Interação com janela de 24h do canal Meta (fonte literal: PRD §10.2)
> "Se a janela estiver fechada, o disparo de follow-up só é permitido via template aprovado." — Esta regra de bloqueio de UI é implementada em 6.5 (disparo manual), mas o worker desta story precisa saber, ao mover para `follow_up`, se o canal ativo é Meta com janela fechada, para sinalizar corretamente ao portal quais mensagens são elegíveis.
