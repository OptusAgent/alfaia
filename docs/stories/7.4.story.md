## Story
**Como** plataforma que não quer números banidos,
**quero** um motor de disparo que respeite delay, horário comercial, template obrigatório no Meta e limites de aquecimento,
**para que** a campanha não vire risco operacional para o tenant.

## Acceptance Criteria
1. Canal UAZAPI: delay aleatório 5–15s, `presence: composing`, horário comercial obrigatório (K1, AC 15.3).
2. Canal Meta: template aprovado obrigatório, sem delay artificial (K2).
3. Contato em opt-out nunca entra em campanha, sem exceção (K3, AC 15.4) — reforça 7.2 no ponto de disparo real.
4. Limite de 1 campanha por contato a cada 15 dias, configurável (K4).
5. Resposta a campanha cria/reabre lead com origem `campanha` (K5, AC 15.5) — usa `identificar_lead` (3.1) com `p_origem='campanha'`.
6. Campanha pausável, retomando de onde parou (K6).
7. UAZAPI: máx. 200 envios/dia nos primeiros 7 dias de número novo (K7, aquecimento).
8. Taxa de falha > 15% em 50 envios → campanha pausa automaticamente e alerta (K8, AC 15.6).

### Schema (fonte literal: PRD §17.8)
```sql
create table campanha_alvos (
  id bigserial primary key,
  campanha_id uuid not null references campanhas(id) on delete cascade,
  contato_id uuid not null references contatos(id) on delete cascade,
  status text not null default 'pendente',
  wa_message_id text,
  enviado_em timestamptz,
  unique (campanha_id, contato_id)
);
```
