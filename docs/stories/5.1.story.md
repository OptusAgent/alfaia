## Story
**Como** plataforma que nunca escreve no domínio do ERP,
**quero** uma camada anticorrupção com implementação mock obrigatória sob o mesmo contrato da real,
**para que** o desenvolvimento de E3/E4 não fique bloqueado esperando o contrato real da WebLocação fechar (I8, Q1–Q3 ainda abertas).

## Acceptance Criteria
1. Implementação mock com o mesmo contrato de §7.2, ativável por env `WL_MODO=mock|real` (I8).
2. Nenhum campo do ERP vaza para o domínio interno sem tradução — camada anticorrupção (I7).
3. Toda chamada (mock ou real) é logada em `wl_chamadas` com latência e status (I3).
4. Timeout de 8s; falha nunca derruba a conversa — retorna erro tratável para a IA acionar transbordo (I2).
5. Retry com backoff em 5xx (máx. 2 tentativas); 4xx sem retry (I4).
6. Auth por chave por tenant, em coluna criptografada, nunca exposta ao client (I1).

## Dev Notes

### Por que esta story pode (e deve) começar cedo
Diferente das demais stories deste épico (5.2–5.4), esta não depende de nenhum contrato real fechado — só do schema base (Épico 1). Pode rodar em **paralelo** a E2/E3/E4, entregando o mock que 4.3 (motor de IA) consome via `WL_MODO=mock`. Recomendação do @sm: iniciar logo após 1.1/1.2, sem esperar E2/E3/E4 terminarem. Ver ordem global em `docs/prd/README.md` (a atualizar com esta recomendação).

### Contrato esperado (fonte literal: PRD §7.2)
```http
GET  /produtos?data_inicio=&data_fim=&categoria=&tamanho=&cor=&estilo=&q=
     → [{ id, codigo, nome, categoria, tamanho, cor, estilo, valor_locacao, status, foto_url }]

GET  /produtos/{id}
     → { ...detalhe..., disponivel_em: [{inicio, fim}] }

GET  /agenda/slots?tipo=&data_inicio=&data_fim=
     → [{ data, hora, vagas_totais, vagas_livres }]

POST /agenda
     body: { tipo, data, hora, cliente_nome, cliente_telefone, produto_id?, observacao? }
     → { id, status }

GET  /agenda?data_inicio=&data_fim=
     → [{ id, tipo, data, hora, cliente_nome, cliente_telefone, produto, origem }]
```

### Regras de integração (fonte literal: PRD §7.3, I1–I8)
| # | Regra |
|---|---|

| I2 | Timeout 8s; falha nunca derruba a conversa — IA informa que vai confirmar e abre transbordo |

### Schema (fonte literal: PRD §17.7)
```sql
create table wl_integracao (
  tenant_id uuid primary key references tenants(id) on delete cascade,
  base_url text not null,
  api_key text not null,
  loja_ref text,
  modo text not null default 'mock',
  ativa boolean not null default true,
  ultimo_sync_em timestamptz
);

create table wl_chamadas (
  id bigserial primary key,
  tenant_id uuid not null references tenants(id) on delete cascade,
  metodo text, rota text,
  status_code int, latencia_ms int,
  erro text,
  criado_em timestamptz not null default now()
);
```
