## Story
**Como** operador Optus,
**quero** editar o nome da persona, o texto de identidade e os parâmetros de `ia_config`,
**para que** cada tenant tenha um tom de atendimento próprio, sem tocar nas regras invioláveis.

## Acceptance Criteria
1. Operador edita a persona (bloco 1 de §19.1) → as regras invioláveis (bloco 2, não editável) permanecem intactas no prompt final montado (AC 19.1).
2. Todos os parâmetros de `ia_config` (§17.9) editáveis pela UI restrita a `operador`: `persona_nome`, `prompt_sistema`, `modelo`, `temperatura`, `janela_retomada_dias` (1–90), `janela_silencio_horas`, `max_tentativas_followup`, `intervalo_tentativas_horas`, `disparo_followup_automatico`, `pausa_transbordo_minutos`, `horario_comercial`.
3. Rota `PATCH /api/automacoes/{chave}`-equivalente para `ia_config` (não listada explicitamente em §18.2 — @dev deve adicionar rota simétrica seguindo o mesmo padrão de auth `x-internal-token`/permissão).

## Dev Notes

### Por que logo após o Épico 4 na sequência global (não dentro dele)
`ia_config` e a montagem de prompt em 4 blocos já existem desde 4.3 (motor de IA) — esta story é a **UI de edição** sobre um schema que já existe. Recomendação do @sm: sequenciar logo após E4 fechar, para permitir ajuste de persona antes do piloto, mesmo que o PRD agrupe esta story dentro do Épico 8 (Configuração) numericamente.

### Schema (fonte literal: PRD §17.9)
```sql
create table ia_config (
  tenant_id uuid primary key references tenants(id) on delete cascade,
  persona_nome text not null default 'Atendente',
  prompt_sistema text not null,
  modelo text not null default 'claude-sonnet-4-6',
  temperatura numeric(2,1) not null default 0.3,
  janela_retomada_dias int not null default 7 check (janela_retomada_dias between 1 and 90),
  janela_silencio_horas int not null default 24,
  max_tentativas_followup int not null default 3,
  intervalo_tentativas_horas int not null default 48,
  disparo_followup_automatico boolean not null default false,
  pausa_transbordo_minutos int not null default 30,
  horario_comercial jsonb not null default '{"inicio":"09:00","fim":"18:00","dias":[1,2,3,4,5,6]}'::jsonb
);
```

### Estrutura do prompt (fonte literal: PRD §19.1)
"O prompt é montado em quatro blocos, nesta ordem: identidade e persona (de `ia_config`) → regras invioláveis → contexto do lead (§9.5) → histórico. Só o primeiro bloco é editável pelo operador; os demais são gerados pelo sistema."
