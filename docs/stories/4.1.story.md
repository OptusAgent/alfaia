## Story
**Como** motor de atendimento,
**quero** agrupar mensagens do mesmo contato chegadas em uma janela curta antes de acionar a IA,
**para que** o lead que manda 4 mensagens em 5 segundos receba uma única resposta coerente, não quatro (AC 8.4).

## Acceptance Criteria
1. Buffer implementado via `debounce_buffer` com consumo por `FOR UPDATE SKIP LOCKED` — concorrência multi-processo sem duplo processamento (Decisão A5, §17.6).
2. 4 mensagens em 5 segundos do mesmo contato resultam em uma única invocação do motor considerando as quatro (AC 8.4).
3. Índice único parcial garante no máximo um registro de debounce não bloqueado por conversa (`debounce_um_por_conversa`).
4. Loop contínuo (`debounce_worker`, job de §18.3) consome o buffer a cada ~2s.

## Dev Notes

### Schema e query de consumo (fonte literal: PRD §17.6)
```sql
create table debounce_buffer (
  id bigserial primary key,
  tenant_id uuid not null,
  conversa_id uuid not null references conversas(id) on delete cascade,
  processar_em timestamptz not null,
  bloqueado_em timestamptz,
  criado_em timestamptz not null default now()
);
create unique index debounce_um_por_conversa on debounce_buffer(conversa_id)
  where bloqueado_em is null;

select * from debounce_buffer
where processar_em <= now() and bloqueado_em is null
order by processar_em
for update skip locked
limit 20;
```

### Requisito de portabilidade (regra de projeto)
Conforme `.claude/rules/alfaia-stack-deploy.md`: jobs agendados (incluindo `debounce_worker`) devem ser implementados como loop/cron **dentro do próprio worker FastAPI**, nunca amarrados a serviço proprietário de nuvem (Cloud Scheduler/Cloud Tasks) sem equivalente rodável em VPS — a estratégia de deploy migra de Cloud Run (dev) para VPS EasyPanel/Dockplot (produção pós-venda).

### Dependência
Depende de `conversas` (criada nesta story ou reaproveitada de 2.2, conforme decisão do @dev sobre agrupamento de migrations) e de `mensagens` (§17.5).

### Testing
§23.1 não lista debounce isoladamente; AC 8.4 é o critério formal. Testar com relógio controlado (não sleep real) para evitar flakiness.
